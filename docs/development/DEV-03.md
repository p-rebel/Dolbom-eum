### 원칙 (2026-11-12 김재현)

1. **화면 구성과 내용은 팀 문서에 근거한다.** D-02 화면 정의, D-04 API, D-05 업무 흐름, expected-results, DEV-01에 있는 화면·항목·문구·동작만 만든다. 근거 없는 요소는 넣지 않는다.
2. **시각 디자인과 UI 패턴은 KRDS를 따른다.** D-02의 배치 그림은 정보와 순서를 나타내는 것으로 보고, 모양은 KRDS 컴포넌트로 만든다. KRDS 코드 키트에는 페이지 틀이 없으므로 [KRDS 누리집](https://www.krds.go.kr/html/site/service/service_04_05.html)의 구성(흰 바탕, 헤더·주 메뉴, 경로 표시, 큰 쪽 제목, 제목·구분선으로 나눈 영역, 오른쪽 ‘이 페이지의 구성’)을 레퍼런스로 삼는다. 커스터마이징은 색상·로고 같은 브랜딩만 하고 구조·행동 패턴은 유지한다(활용방법 p14).
3. **팀 문서에 없더라도 KRDS 체크리스트의 해당 항목은 지킨다.** 목표 적용 수준은 ‘필수’ 전부이며, ‘권장’·‘우수’는 팀 문서에 근거가 있을 때만 넣는다(활용방법 p13).
4. **팀 문서와 KRDS가 충돌하는 부분만 검토한다.** 아래 ‘문서와 KRDS 충돌’ 표에 모으고 이동수 님 확인을 받는다.
5. **KRDS 항목을 지킬 수 없으면 예외로 기록한다.** 시연 앱의 성격(가상 계정, 공식 정부서비스 아님) 때문에 해당하지 않는 항목은 아래 ‘KRDS 예외’ 표에 이유와 함께 남긴다.

### 적용 대상과 스타일 유형

- 돌봄e음은 **공식 디지털 정부서비스가 아니다.** 가이드라인 p18·19와 체크리스트에 따라 공식 배너(마스트헤드)와 운영기관 식별자를 쓰지 않는다. 정부 상징·KRDS 로고도 쓰지 않는다.
- 독자 서비스명을 쓰므로 확장형 스타일에 가깝지만, 색상·서체·형태는 **표준형 값**(Pretendard GOV, 본문 17px, 굵기 400·700, KRDS 토큰)을 그대로 쓴다.

### KRDS 피그마 화면 틀 비교 (2026-11-12)

KRDS 피그마 ‘📚 Pattern’의 PC 프레임과 5개 화면을 비교했다. 원칙 1·4에 따라 문서 근거와 충돌하지 않는 시각·배치 차이만 고쳤다.

- 크기 규칙(피그마 실측): 한 줄에 놓인 입력칸과 버튼은 같은 높이(56/56). 필터 상자 안 선택상자 48px. 폼 하단 버튼 64px. KRDS CSS는 크기 클래스가 없는 입력칸·선택상자를 large(56px)로, `krds-btn medium`을 48px로 그리므로 옆에 둘 때는 크기 클래스를 맞춘다.

### 결정

화면은 [KRDS(대한민국 정부 디자인 시스템)](https://www.krds.go.kr)의 HTML 컴포넌트 키트 `krds-uiux` **1.1.0**(npm, 버전 고정)을 그대로 쓴다. 공공 서비스 시연이므로 정부 표준의 색상·서체·컴포넌트·패턴을 따르고, 화면별 디자인 판단을 줄인다. (2026-11-12 김재현)

- 저작권: 저작권법 제24조의2(공공저작물의 자유이용)에 따라 KRDS의 디자인·코드·문서는 출처 표기 후 별도 허락 없이 이용할 수 있다. [KRDS 저작권정책](https://www.krds.go.kr/html/site/utility/utility_06.html)
- 출처 표기: `frontend/src/styles.css` 머리말에 기록한다.
- 서체: Pretendard GOV(SIL OFL 1.1). 패키지에 포함된 woff2를 앱이 직접 제공하며 외부 CDN을 쓰지 않는다.

### 사용 규칙

| 구분 | 규칙 |
| --- | --- |
| 가져온다 | `resources/css/component/output.css`(토큰·공통·컴포넌트), 서체, 아이콘. 컴포넌트 예시 HTML의 클래스·구조·`aria` 속성을 JSX로 옮긴다. |
| 가져오지 않는다 | `ui-script.js`. 페이지 로드 시 한 번 DOM을 찾아 이벤트를 붙이고 DOM을 직접 바꾸는 방식이라, 화면을 다시 그리는 React와 충돌한다. 탭·모달 등 동작은 React로 구현한다. |
| 쓰지 않는다 | 마스트헤드(‘대한민국 공식 전자정부 누리집’), 식별자(‘○○부 누리집’), KRDS 로고, 기관 정보 푸터. 시연 앱이 실제 정부 누리집으로 오인될 수 있다. |
| 날짜 입력 | KRDS 달력은 JS 의존이 커서 브라우저 기본 `type="date"`에 `krds-input`을 적용한다. |
| 앱 CSS | KRDS에 없는 배치만 `styles.css`에 KRDS 토큰(`--krds-*`)으로 작성한다. KRDS는 `1rem = 10px`이다. |
| 공통 부품 | 반복되는 KRDS 구조는 `src/components/`에 감싼다. `TextField`(입력란·비밀번호 표시), `FormFields`(선택상자·라디오·체크박스·긴 글), `Feedback`(로딩·오류·빈 결과·상태 배지), `Pagination`, `Modal`(KRDS 모달 구조, 동작은 React). |
| KRDS 주의점 | `legend`는 KRDS가 화면에서 숨기므로 라디오 묶음 제목을 `form-tit`으로 한 번 더 표시한다. 표는 `krds-table-wrap mob-scroll`, 결과 목록은 `krds-structured-list type-full`을 쓴다. 라디오·체크박스는 레이블을 눌러 선택하는 구조다. |
