## 4. 구현 시 지킬 조건 (설계 변경 아님)

- Python `sqlite3`의 암묵적 트랜잭션을 끄고(`isolation_level=None`) `BEGIN IMMEDIATE`를 직접 실행한다. 그렇지 않으면 쓰기 잠금 시점이 설계와 달라진다.
- 연결마다 `PRAGMA foreign_keys=ON`과 `busy_timeout`(5초 이상)을 설정한다. 설정하지 않으면 동시 저장의 두 번째 요청이 `409` 대신 `database is locked`로 끝나 `500`이 된다.
- `journal_mode=WAL`을 사용한다. 쓰기 중에도 읽기를 막지 않는다.
- 백업은 SQLite 백업 API(`sqlite3 .backup` 또는 `Connection.backup`)를 쓴다. WAL 모드에서 실행 중인 DB 파일만 복사하면 `-wal` 파일의 변경이 빠진다. AC-07 복구 절차에 이 내용을 적는다.
- `Origin` 허용값과 쿠키 `Secure` 여부는 환경값으로 둔다. 로컬은 `http://127.0.0.1:5173`에 `Secure=false`, 팀 서버는 HTTPS 주소에 `Secure=true`. `localhost`와 `127.0.0.1`은 다른 출처라는 점을 팀 실행 안내에 적는다.
- 가상 계정 비밀번호는 저장소 밖의 환경값이나 파일에서 시드 스크립트로 읽어 해시로 저장한다.

## 5. 서버·배포 미결 사항 (Q-05, H-02 남은 결정)

| 미결 | 제안 | 결정 필요 |
| --- | --- | --- |
| 배포 대상 | AWS Lightsail 또는 EC2 소형 인스턴스 1대. 디스크가 유지되는 VM이어야 한다. 컨테이너가 재시작될 때 디스크가 지워지는 PaaS는 SQLite를 잃는다. | 이동수 (비용·계정 소유) |
| 도메인과 HTTPS | D-04가 팀 공유 환경의 HTTPS·`Secure` 쿠키를 요구한다. 도메인과 Caddy 자동 인증서를 쓴다. | 이동수·양이수 |
| 팀 접근 범위 (DEC-03) | 앱 로그인 + 방화벽은 80/443만. SSH 접근자는 양이수·이동수로 제한 | 이동수 |
| 프론트 제공 방식 | FastAPI가 `frontend/dist`를 제공하고, `/api` 외 경로는 `index.html`로 보낸다. 이 처리가 없으면 `/cases/:id`를 새로고침할 때 404가 난다. 첫 통합 기준인 ‘새로고침 후 재조회’와 직결된다. | 양이수 구현, 김재현 확인 |
| 실행 방식 | uvicorn 워커 1개를 systemd로 실행. 시연 규모에서는 충분하고 SQLite 잠금 경합이 줄어든다. | 양이수 |
| DB 경로·초기화·백업 | 저장소 밖 고정 경로(예: `/var/lib/dolbomeum/app.db`), 초기화·시드·백업 스크립트, 배포 전 자동 백업 | 양이수, B-03 안내에 기록 |
| 빌드 위치 | 프론트는 로컬에서 `npm ci && npm run build`로 빌드해 `dist`만 올리거나, 서버에 Node 22를 설치 | 양이수·김재현 |

### Supabase를 쓰지 않는 근거

- Supabase는 DB만 대신한다. FastAPI는 여전히 어딘가에서 실행해야 하므로 **서버 운영이 없어지지 않는다.**
- DB만 Postgres로 바꾸면 D-04(세션·API)는 유지되지만, D-03의 `BEGIN IMMEDIATE`·SQLite 전제와 AC-07 백업·복구·초기화 절차를 다시 써야 한다.
- 공단 데이터는 약 9만 행이고 업무 데이터는 시연 사례 몇 건이다. SQLite 한 파일로 충분하다.
