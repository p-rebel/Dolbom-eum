# D-05 업무와 상태 전이

기준은 [D-01 요구사항과 범위](D-01_scope.md)의 C-01과 C-06이다. 상태는 시연에서 저장한 기록을 나타낸다. 공단 판정과 회의 결정은 각각 가상 결과와 회의 결과를 담당자가 입력하는 방식으로 다룬다. [R-01 업무 흐름](https://github.com/p-rebel/Dolbom-eum/blob/621f082/docs/research/R-01.md) · [R-04 대표 사례](https://github.com/p-rebel/Dolbom-eum/blob/621f082/docs/research/R-04.md)

## 신청 건의 진행

| 동작 | 실행 역할 | 필요한 입력과 조건 | 저장 결과와 다음 상태 |
| --- | --- | --- | --- |
| 신청 접수 | 읍면동 | 소속 읍면동의 가상 프로필, 접수일, 안내방식, 증빙 확인 | 대상자·대리 신청인·안내대상을 구분해 저장 → `RECEIVED` 접수 완료 |
| 사전조사 기록 | 읍면동 | `RECEIVED`. 조사일·방법, C-01의 통합판정조사군 결과 | 사전조사 기록 → `SCREENED` 사전조사 완료 |
| 판정 결과 기록 | 시군구 | `SCREENED`. 가상 공단 판정일, 시군구 수신일, 지원계획 진행 결과 | 판정 기록 → `ASSESSED` 판정 기록 완료 |
| 계획 초안 저장 | 읍면동 | `ASSESSED` 또는 `PLAN_DRAFTED`. 수립일, 목표, 조회한 공단 서비스 1~5개 | 초안을 생성하거나 전체 교체 → `PLAN_DRAFTED` 지원계획 초안 저장 완료 |
| 회의 결과와 계획 확정 | 시군구 | `PLAN_DRAFTED`. 회의일과 승인 결과, 계획에 한 개 이상 항목 | 회의 승인 기록과 계획 확정 → `PLAN_CONFIRMED` 지원계획 확정 |
| 계획 안내 기록 | 시군구 | `PLAN_CONFIRMED`. 안내 기록 전, 확정 후 안내일 | 접수 때 정한 안내대상과 방식으로 안내한 사실 기록. 상태는 `PLAN_CONFIRMED` |
| 서비스 연계 기록 | 시군구 | `PLAN_CONFIRMED` 또는 `SERVICE_TRACKING`. 안내 완료, 확정 계획에서 연계 기록이 없는 항목의 ID, 연계일·방식 | 항목별 연계 사실 저장 → `SERVICE_TRACKING` 연계·제공 기록 중 |
| 서비스 제공 현황 기록 | 시군구 | `SERVICE_TRACKING`. 해당 항목의 연계 기록, 확인일·제공 상태, 필요 시 사유 | 항목별 현황을 저장하거나 갱신. 상태는 `SERVICE_TRACKING`. 모든 항목의 연계·제공 현황이 기록되면 시군구의 다음 작업은 ‘읍면동 최초 모니터링 대기’로 표시하고, 모니터링 전 정정은 항목별 ‘제공 현황 수정’으로 한다 |
| 최초 모니터링 기록 | 읍면동 | `SERVICE_TRACKING`. 모든 항목에 연계·제공 현황 기록(확인 중 포함), 확인일·방법·상태 변화·검토 필요 여부. 후속 검토가 필요하면 사유 필수. 새로 확인한 항목의 상태·사유는 추가 입력 | 제공 현황을 바탕으로 새 관찰을 반영해 모니터링 결과 저장 → `FIRST_MONITORING_RECORDED` 최초 모니터링 기록 완료 |

최초 모니터링 기록 완료는 이번 시연 경로의 종료 지점이다. 계획 변경이나 종결 검토가 필요한 경우 모니터링에 검토 필요 여부와 사유를 남겨 시군구가 조회한다.

‘후속 검토 필요’를 선택하면 양쪽 공백을 제외한 사유가 1~200자여야 한다. 사유가 비어 있으면 모니터링 기록을 저장하지 않고 입력 화면에서 사유를 요청한다. [D-04 입력 검증](D-04_api.md#필드-값과-입력-검증)

시군구의 제공 현황은 기록 주체와 확인일을 보존한다. 읍면동이 모니터링에서 새로 확인한 상태·사유는 모니터링 결과에만 저장한다. 예를 들어 B의 기존 ‘확인 중’과 읍면동의 ‘미개시’ 관찰을 한 사례에서 함께 조회할 수 있다.

## 서비스별 연계와 제공 상태

| 연계 방식 | 표시와 기록 |
| --- | --- |
| `DEPARTMENT_REFERRAL` 부서·공단 의뢰 | 담당 부서 또는 공단을 가상 수신처로 기록 |
| `PROVIDER_REFERRAL` 제공기관 의뢰 | 확정된 계획 항목의 제공기관을 가상 의뢰처로 기록. 기관명이 있는 자료 행만 이 방식을 선택할 수 있음 |
| `PERSON_GUIDANCE` 대상자 안내 | 대상자에게 기관 선택 정보를 안내한 사실을 기록. 화면의 카탈로그 기관명은 후보로 표시 |

제공 현황 값은 `UNKNOWN` 확인 중, `IN_USE` 이용 중, `NOT_STARTED` 미개시, `DECLINED` 이용 거부다. 확인 중을 포함한 각 상태는 담당자가 확인일과 함께 명시적으로 저장한다. 미개시와 이용 거부에는 사유가 필요하다. 서비스 한 건의 미개시나 거부만으로 신청 건의 진행 상태를 종결로 변경하지 않는다. [R-03 업무 분기](https://github.com/p-rebel/Dolbom-eum/blob/621f082/docs/research/R-03.md)

## 공통 전환 조건

- 읍면동은 소속 읍면동 건, 시군구는 소속 시군구 건에 접근한다. 생성 시 관할은 가상 계정과 프로필로 검증한다. 동작 권한은 위 표를 따른다.
- 날짜는 한국 시간의 업무일자다. 접수일 ≤ 조사일 ≤ 판정일 ≤ 판정 수신일 ≤ 계획 수립일 ≤ 회의일 ≤ 안내일 ≤ 항목 연계일 ≤ 항목 제공 확인일 순으로 검사한다. 모니터링일은 모든 항목의 제공 확인일 이후 또는 같은 날이어야 한다. 동일 일자 처리가 가능하다. 주기나 기한 계산은 별도 검토 후 추가한다.
- 사전조사·판정·확정·안내·항목 연계·최초 모니터링은 각각 한 번 기록한다. 초안은 확정 전 교체할 수 있고, 제공 현황은 최초 모니터링 전 갱신할 수 있다. 확정 후 초안 수정 요청은 상태 충돌로 처리한다.
- 최초 접수는 버전 1과 처리 이력 한 건을 만든다. 이후 기록 동작이 성공할 때마다 버전과 이력이 하나씩 증가한다. 동일 접수의 재시도와 거절된 요청에서는 추가 기록이 생기지 않는다. 사례, 관련 기록, 이력을 한 트랜잭션으로 저장한다. [D-04 API 계약](D-04_api.md)
