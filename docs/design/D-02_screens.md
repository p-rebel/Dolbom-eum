# D-02 화면 정의

읍면동과 시군구 담당자는 같은 신청 상세 화면에서 기록을 확인한다. 입력 버튼은 상세 응답의 `allowedActions`에서 구성한다. 공단 조회 화면은 계획 초안 작성 중에도 열 수 있다. 화면 상태의 기준은 [D-05 업무와 상태 전이](D-05_workflow.md), 필드와 오류는 [D-04 API 계약](D-04_api.md)을 따른다.

## 화면과 이동

| 화면 | 경로 | 사용 주체 | 화면 구성과 동작 |
| --- | --- | --- | --- |
| UI-01 가상 계정 로그인 | `/login` | 읍면동·시군구 | 계정명과 비밀번호 입력 → 신청 목록. 역할과 관할은 로그인 후 서버에서 받는다. |
| UI-02 신청 목록 | `/cases` | 읍면동·시군구 | 접수번호, 가상 대상자 표시명, 접수일, 진행 상태를 표시. 상태 필터와 페이지 이동. 읍면동에만 새 접수 버튼 표시. 행을 선택하면 신청 상세로 이동. |
| UI-03 새 접수 | `/cases/new` | 읍면동 | 가상 프로필 선택 후 대상자·대리 신청인·안내대상 미리보기. 접수일, 안내방식, 증빙 확인 체크를 입력. 저장 성공 후 신청 상세로 이동. |
| UI-04 신청 상세 | `/cases/:caseId` | 읍면동·시군구 | 상단에 접수번호, 가상 대상자, 관할, 상태, 다음 작업 표시. 접수·조사, 계획, 연계·제공, 모니터링, 처리 이력 순서로 배치. |
| UI-05 공단 서비스·기관 조회 | `/catalog` 또는 계획 입력 영역 | 읍면동·시군구 | 시도·시군구·대분류·검색어, 프로그램·기관 검색 결과, 출처·기준일. 독립 화면에서는 조회, 계획 초안에서는 항목 선택 가능. |

공통 상단에 가상 데이터 시연임을 표시하고, 계정 역할·관할과 로그아웃을 배치한다. 화면 이동 시 선택한 페이지의 제목으로 초점을 옮긴다. 입력란에는 연결된 레이블과 오류 문구를 제공하고, 상태는 색상과 텍스트를 함께 사용한다.

## 기본 화면 배치

```text

다음 작업  지원계획 초안 저장

[접수·조사] [계획] [연계·제공] [모니터링] [처리 이력]

지원계획 초안
수립일  [              ]    지원 목표 [                            ]

[이전]     1페이지     [다음]
```

## 신청 상세

| 영역 | 표시할 기록 | 편집과 저장 |
| --- | --- | --- |
| 접수·조사 | 가상 대상자·신청인·안내대상, 접수일, 증빙 확인, 사전조사와 판정 수신일 | 읍면동이 조사일·방법·결과 입력. 시군구가 가상 판정일·수신일·결과 입력. 두 저장 동작을 구분한다. |
| 계획 | 목표, 수립일, 서비스 후보, 회의 결과, 안내일 | 읍면동이 목표와 후보 1~5개를 저장. 시군구가 회의 결과로 계획을 확정하고 안내일을 별도 저장. 확정 전 저장한 서비스 목록을 확정 화면에서 재확인한다. |
| 연계·제공 | 행마다 프로그램, 출처, 연계 방식·일자, 제공 상태·확인일·사유 | 시군구가 서비스 항목별로 연계와 제공 현황을 별도 저장. 부서·공단 의뢰 시 수신처 입력. 대상자 안내에서는 제공기관을 후보로 표시. 미개시·거부 선택 시 사유를 필수로 표시한다. |
| 모니터링 | 기록일·방법, 상태 변화, 검토 필요 여부, 기존 제공 현황과 모니터링 확인 결과 | 읍면동이 기존 현황을 보면서 새로 확인한 항목의 상태·사유를 입력한다. ‘후속 검토 필요’를 선택하면 바로 아래에 ‘후속 검토 사유’ 필수 입력란을 표시한다. C-06의 B는 ‘기존 제공 현황 · 확인 중’과 ‘모니터링 확인 · 미개시’를 함께 표시한다. 누락된 항목은 서비스명과 빠진 값을 표시한다. |
| 처리 이력 | 처리 시각, 담당 역할, 수행 동작, 상태 변화와 변경 요약 | 최근 처리부터 표시. 확정, 안내, 연계, 제공 현황의 시점을 각각 확인할 수 있다. |

서비스 조회를 계획 안에서 열면 사례의 시도·시군구를 기본 필터로 적용한다. 검색 결과를 펼쳐 분류, 기관 주소·연락처, 출처, 기준일을 확인한다. 선택한 행은 초안에만 추가하고, 초안 저장까지 입력 내용을 유지한다. 시군구와 독립 카탈로그 화면에는 계획에 추가하는 버튼을 표시하지 않는다. 기관명·주소·연락처 등 결측값은 화면에 ‘자료 없음’으로 표시한다.

상세에서 동작할 수 있는 사람이 바뀌면 상단에 다음 담당 역할을 표시한다. 예를 들어 사전조사를 마친 읍면동 화면에는 ‘시군구 판정 결과 기록 대기’를 표시한다. 계획 항목이 모두 기록되면 읍면동에 ‘최초 모니터링 기록’ 버튼을 제공한다. 완료 화면에는 모니터링 기록일, 후속 검토 필요 여부, 서비스별 상태·사유를 표시한다. ‘후속 검토 필요’ 바로 아래에는 저장한 후속 검토 사유를 표시한다. [표시 문구와 값](expected-results.md)

## 빈 상태와 오류 처리

| 상황 | 사용자에게 보일 결과 |
| --- | --- |
| 데이터 로딩 또는 저장 중 | 로딩 상태를 알리고 해당 저장 버튼을 잠근다. 완료 후 저장 결과와 다음 동작을 표시한다. |
| 신청 목록 또는 검색 결과 0건 | 목록은 조건을 풀 수 있는 초기화 동작, 카탈로그는 지역·검색어를 바꿀 수 있는 동작을 제공한다. |
| 필수값·날짜·현황 사유 오류 `422` | 필드 옆에 원인을 표시하고 첫 오류 필드로 이동한다. 입력값을 유지한다. |
| 저장 충돌 `409` | 상세 편집에서는 최신 기록을 불러오고 입력을 재확인용으로 유지한다. 새 접수의 요청 키 충돌은 신청 목록에서 기존 접수 여부를 확인하는 동작으로 안내한다. |
| 세션 만료 `401` | 로그인 화면으로 이동한다. |
| 동작 권한 부족 `403` 또는 사례 접근 불가 `404` | 처리 권한 부족 또는 사례를 찾을 수 없음을 표시하고 신청 목록으로 돌아갈 수 있게 한다. |
| 연결 실패 또는 서버 오류 | 조회 재시도 동작을 제공한다. 상세 저장 응답을 받지 못하면 상세를 다시 불러온다. 새 접수의 저장 여부가 불명확하면 최초 요청의 키와 본문을 함께 보관하고 동일하게 재시도해 접수 결과를 확인한다. |
