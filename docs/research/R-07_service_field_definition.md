

## ① 조사 개요

| 항목 | 내용 |
| --- | --- |
| 조사 산출물 ID | R-07 |
| 조사명 | 돌봄e음 수집 자료 필드 정의 |
| 조사 담당자 | `bomi-data` |
| 조사 목적 | 국민건강보험공단 통합돌봄 서비스 지원 데이터를 기준으로 지역별 서비스 정보를 구성하고, 보건복지부 지방정부 서비스 메뉴판으로 프로그램 내용과 대상자 정보를 보완하기 위해 필요한 필드의 의미, 출처, 자료 간 연결 기준, 관리 원칙을 정의한다. |
| 조사 범위 | 기준 자료(공단 CSV) 8개 필드, 보완 자료(보건복지부 메뉴판 PDF) 2개 필드, 출처 관리 항목 4종. 출처 관리 항목은 자료별로 구분하여 관리하며, 실제 저장 구조는 개발 단계에서 확정한다. |
| 조사 상태 | 1차 정의 초안 |

## ② 수집 데이터 필드 정의

### 2-1. 기준 자료 필드 (원본에 존재하는 필드 — 공단 CSV)

| 필드명 | 정의 | 데이터 형식 | 수집 출처 | 비고 |
| --- | --- | --- | --- | --- |
| 시도 | 서비스 제공기관이 속한 시도 | 문자열 | 공단 CSV | 행정구역 코드와의 연결은 R-08 이후 검토 |
| 시군구 | 서비스 제공기관이 속한 시군구 | 문자열 | 공단 CSV | 지역 단위 연결 키로 사용 검토 |
| 서비스 제공기관명 | 통합돌봄 서비스를 제공하는 기관의 명칭 | 문자열 | 공단 CSV | 원문 표기 보존 |
| 기관연락처 | 서비스 제공기관의 연락처 | 문자열 | 공단 CSV | 숫자형으로 가정하지 않음. |
| 기관주소 | 서비스 제공기관의 주소 | 문자열 | 공단 CSV | 원문 표기 보존. |
| 대분류 | 공단 자료의 서비스 대분류 | 문자열 | 공단 CSV | 지역 메뉴판의 대분류와 같은 체계인지 미확인 |
| 중분류 | 공단 자료의 서비스 중분류 | 문자열 | 공단 CSV | 지역 메뉴판의 중분류와 같은 체계인지 미확인 |
| 프로그램 명칭 | 공단 자료에 기재된 프로그램의 명칭 | 문자열 | 공단 CSV | 단독으로 메뉴판 사업과 동일 사업이라고 판단하지 않음 |

### 2-2. 보완 자료 필드 (메뉴판에서 보완 예정 — 연결이 확인된 경우에만 입력)

| 필드명 | 정의 | 데이터 형식 | 수집 출처 | 비고 |
| --- | --- | --- | --- | --- |
| 프로그램 내용 | 프로그램의 내용 설명 | 문자열 (긴 텍스트) | 메뉴판 PDF의 `사업내용` 또는 `내용` | 메뉴판마다 컬럼명이 다름(R-06). 연결 불확실 시 공란 |
| 대상자 | 프로그램의 지원 대상 설명 | 문자열 (긴 텍스트) | 메뉴판 PDF의 `지원대상` 또는 `대상자 범주` | 메뉴판마다 컬럼명이 다름(R-06). 연결 불확실 시 공란 |

### 2-3. 출처 관리 필드 (추가로 생성·관리하는 메타데이터)

| 필드명 | 정의 | 데이터 형식 | 수집 출처 | 비고 |
| --- | --- | --- | --- | --- |
| 원본자료명 | 정보를 가져온 자료의 공식 명칭 | 문자열 | R-05의 자료명 | 기준 자료와 보완 자료를 구분하여 기록 |
| 원본 URL | 정보를 가져온 자료의 원문 주소 | 문자열 (URL) | R-05의 원문 URL | 기준 자료와 보완 자료를 구분하여 기록 |
| 자료 기준일 | 원본 자료가 제시하는 기준 시점 | 날짜 | 원본 자료의 표기 | 원본의 기준 시점 표기를 보존한다. 정확한 날짜로 변환할 수 없는 경우 임의로 일자를 생성하지 않는다. |
| 데이터 수집일 | 프로젝트에서 자료를 수집한 날짜 | 날짜 | 수집 기록 | 자료 기준일과 구분 |

출처 구분 관리 방안 (잠정):

- 출처 관리 필드 4개는 기준 자료(공단 CSV)와 보완 자료(메뉴판 PDF)에 대해 각각 기록하여, 프로그램 내용·대상자 값이 어느 자료에서 왔는지 추적할 수 있게 한다.
- 구체적인 저장 구조는 확정하지 않으며, 개발 담당자와 협의한다.

## ③ 자료 간 연결 기준

아래 기준은 잠정적인 검토 기준이며, 실제 매칭 정확도는 검증되지 않았다.

| 비교 항목 | 공단 데이터 | 메뉴판 | 검토 기준 (잠정) | 주의사항 |
| --- | --- | --- | --- | --- |
| 지역 | 시도, 시군구 | 메뉴판이 속한 지자체 | 시도·시군구가 메뉴판의 지자체와 일치하는지 우선 확인 | 시도 단위 메뉴판과 시군구 단위 서비스의 대응 방식은 R-08에서 확인 |
| 서비스 분류 | 대분류, 중분류 | 지역별 분류 표기 (서울: 대분류·중분류, 대구: 영역 등) | 분류가 의미상 겹치는지 참고 비교 | 분류 체계가 같다고 가정하지 않음 |
| 사업명 | 프로그램 명칭 | 사업명 | 명칭의 일치·유사 여부를 후보 선정의 단서로 사용 | 명칭 일치만으로 동일 사업으로 판단하지 않음 |
| 사업 내용 | (공단 자료에 없음) | 사업내용 또는 내용 | 후보 사업의 내용이 공단 프로그램과 부합하는지 검토 | 내용 부합 여부는 사람이 확인 |

연결 판단 원칙:

| 상황 | 처리 원칙 (잠정) |
| --- | --- |
| 지역, 분류, 사업명, 내용이 함께 부합 | 연결 후보로 기록하고 판단 근거를 남긴다. |
| 명칭만 일치하고 다른 항목이 불일치하거나 확인되지 않음 | 연결하지 않고 미확인으로 둔다. |
| 대응하는 메뉴판 사업이 없음 | 프로그램 내용과 대상자를 공란으로 두고 임의로 입력하지 않는다. |
| 대응 후보가 여러 개 | 하나로 확정하지 않고 후보를 함께 기록하여 검토 대상으로 둔다. |

## ④ 데이터 처리 및 관리 원칙

| 구분 | 원칙 |
| --- | --- |
| 원문 데이터 보존 | 공단 CSV와 메뉴판 PDF의 원문 값을 수정하지 않고 보존한다. 정제 값이 필요하면 원문 값과 구분하여 관리한다. |
| 누락값·미확인 정보 | 원본에 값이 없거나 확인되지 않은 정보는 추정하여 채우지 않고, 누락 또는 미확인 상태로 둔다. |
| 동일 사업명·중복 | 사업명이 같아도 지역, 제공기관, 분류가 다르면 동일 데이터로 합치지 않는다. 중복 판단 기준은 R-08 표본 검토 후 정한다. |
| 지역별 명칭·분류 차이 | 지역별로 다른 사업명과 분류 표기는 원문 그대로 보존하고, 통합 분류 기준은 확정하지 않는다. |
| 출처·기준일 | 모든 값은 출처를 추적할 수 있어야 한다. 자료 기준일과 데이터 수집일을 구분하여 기록한다. |
| 대상자와 신청 자격 | `대상자`는 자료에 기재된 지원대상 설명이며, 개인의 실제 신청 자격이나 선정 결과를 의미하지 않는다. 자격 판단 용도로 사용하지 않는다. |

## ⑤ 후속 작업 전달 사항 (R-08)

| 번호 | 확인 사항 |
| --- | --- |
| 1 | 공단 데이터와 메뉴판의 실제 매칭 가능성 검증: 표본 지역을 정해 ③의 기준으로 연결 가능 여부와 연결이 어려운 사례를 확인한다. |
| 2 | PDF 표 추출 및 누락 여부 확인: 기존 PDF 추출 결과를 원문과 대조하여 누락·깨짐·행 분리 오류 등을 확인하고, 검토가 필요한 항목을 별도로 관리한다. |
| 3 | 지역별 서비스명·분류 차이 검토: 공단 분류와 지역 메뉴판 분류의 대응 상태를 표본에서 확인한다. |
| 4 | 메뉴판에만 존재하는 지역특화 서비스 확인: 공단 데이터에 대응 프로그램이 없는 메뉴판 사업의 존재 여부를 확인한다. |
| 5 | 최종 데이터 구조의 개발 담당자 협의: 본 문서의 필드 정의와 출처 구분 방식을 개발 담당자와 협의하여 조정한다. |

본 문서는 R-08의 추출·정제·가공 작업을 수행하지 않았으며, 최종 DB 스키마, ERD, SQL, API 설계를 포함하지 않는다.
